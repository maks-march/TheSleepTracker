# Почему обновление не работало и что теперь сделано

## Три причины (все исправлены)

### 1. Главная: `version.json` не был больше установленной версии
В репозитории лежало `versionCode: 4`, и в самой APK тоже был `versionCode 4`.
Приложение сравнивает `4 > 4` → **false** → всегда «У вас последняя версия».
Кнопка «Обновить» работала правильно, ей просто нечего было предложить.

**Стало:** `version.json` → `versionCode 5` / `1.4`, APK тоже `5` / `1.4`.

### 2. Две APK с разными подписями
В `apk/` лежали два файла, подписанные **разными** ключами:

| файл | отпечаток SHA-256 |
|---|---|
| `TheSleepTracker.apk` | `e60e5f35…` |
| `app-debug.apk` | `c9ca6ed2…` |

Android не даёт поставить обновление поверх, если подпись отличается —
установка падает с `INSTALL_FAILED_UPDATE_INCOMPATIBLE`, часто вообще без внятного сообщения.
К тому же debug-ключ генерируется заново на каждой машине, то есть подпись «плавала» от сборки к сборке.

**Стало:** лишний `app-debug.apk` удалён, создан **постоянный** ключ
`keystore/thesleeptracker.jks`, он прописан в `app/build.gradle.kts`.
Все будущие сборки подписываются им → обновления встают поверх.
Новый отпечаток: `e97aa8ac…`.

### 3. Не запрашивалось разрешение на установку
С Android 8 приложение не может открыть установщик, пока пользователь
не разрешил ему «установку из неизвестных источников». Проверки не было —
APK скачивался, а установщик **молча не открывался**.

**Стало:** в `update/ApkDownloader.kt` добавлены `canInstall()` и
`openInstallPermissionSettings()`. Если разрешения нет — приложение
показывает подсказку и само открывает нужный экран настроек.

## ⚠️ Что нужно сделать вам

### Шаг 1. Запушить (сейчас это единственное, что осталось)
Коммит `ed9a612` готов локально, но у меня нет доступа к вашему GitHub:

```bash
cd /home/user/SleepTracker
git push origin main
```

Пока это не сделано, на GitHub лежит старый `version.json` с `versionCode 4`
и обновление по-прежнему не предложится.

### Шаг 2. Переустановить приложение на телефоне — **один раз, обязательно**
Версия, которая стоит у вас сейчас, подписана **старым** ключом.
Поверх неё новая уже не встанет, каким бы правильным ни был `version.json`.

Удаление стирает базу, поэтому сначала сохраните записи:

1. **Настройки → «Резервная копия»** — в «Загрузки» ляжет файл
   `TheSleepTracker-backup-ГГГГ-ММ-ДД.json`
2. Удалите TheSleepTracker с телефона
3. Скачайте APK заново:
   https://github.com/maks-march/TheSleepTracker/raw/main/apk/TheSleepTracker.apk
4. Установите
5. **Настройки → «Восстановить из копии»** — выберите сохранённый файл

**Это разовая процедура.** Дальше все обновления будут ставиться прямо из
приложения кнопкой «Обновить»: данные при этом никуда не деваются, потому что
обновление «поверх» базу не трогает — удалять приложение больше не придётся.

### Шаг 3. Разрешить установку (телефон спросит сам)
При первом обновлении Android откроет экран «Установка неизвестных приложений» —
включите переключатель для TheSleepTracker. Тоже один раз.

## Как выпускать следующие версии

Просто запустите скрипт — он сам поднимет версию, соберёт, подпишет
правильным ключом, синхронизирует `version.json` и запушит:

```bash
./release.sh 1.5 "Что нового в этой версии"
```

Скрипт гарантирует главное: **`versionCode` в `version.json` всегда совпадает
с `versionCode` в APK и всегда больше предыдущего**. Именно рассинхрон этих
двух чисел и сломал обновление в прошлый раз.

Если хотите собрать без пуша:

```bash
./release.sh 1.5 "Что нового" --no-push
```

## Почему обновления теперь не теряют данные

- База `sleep.db` лежит во внутреннем хранилище и переживает установку поверх.
  Room настроен **без** `fallbackToDestructiveMigration()`, поэтому молча
  стереть записи при смене схемы он не может.
- Прописаны правила бэкапа (`backup_rules.xml`, `data_extraction_rules.xml`):
  база, настройки и фон попадают в облачную копию и в перенос на новый телефон.
- На случай, когда переустановка всё же нужна (как сейчас, из-за смены ключа),
  в настройках есть «Резервная копия» и «Восстановить из копии».
  Повторный импорт одного и того же файла дубликатов не создаёт.

## Про ключ подписи

`keystore/thesleeptracker.jks` — **не теряйте его**. Если он пропадёт, вы больше
не сможете выпускать обновления поверх установленных: пользователям придётся
снова удалять приложение. Сделайте копию в надёжном месте.

Пароли можно поменять — создайте `keystore.properties` по образцу
`keystore.properties.example` (этот файл в git не попадает).
